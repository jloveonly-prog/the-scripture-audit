# 🏹 SKILL-39: TYPE-AL — Equivocation Detection
**"Catches the fallacy of subtly shifting the same word to a different meaning"**

> **When to invoke**: When an opponent uses the same word with different meanings during an argument to cause confusion.
> Especially when changing the definitions of key terms like "explicit", "evidence", or "tradition" depending on the context.
>
> **One-line definition**: *"Same word, different meaning — the moment the argument collapses."*

---

## Invocation Conditions
`
[Universal]
1. When an opponent changes the definition of a key term during an argument
   (e.g., "explicit", "evidence", "tradition", "inspiration", "miracle", "salvation", etc.)
2. When using the same word with meaning A when advantageous, and meaning B when disadvantageous
3. When the foundation of the argument is shaken by the shifting definition of terms
4. [Self-Check — added v1.1] **Our own (BVCAP) argument** ignores the KJV's distinction of the same root into uppercase (proper title) and lowercase (general category), and applies the conclusion of one usage directly to the other → detailed procedure in TYPE-AL-cap sub-protocol below

[Typical Code] Invoke immediately upon detecting the following patterns:
  - The same word is used with a different meaning in the first and second half of the argument
  - Saying "that is different" while the logical structure is the same
  - The opponent applying a broad definition to advantageous cases, and a narrow definition to disadvantageous cases
  - [Self-Check] Automatic transfer from uppercase→lowercase, such as "Because it is the Son (coronation declaration) in Heb 1:5, the sons (creation category) in Job 38:7 are also automatically excluded"
`

## Execution Steps
`
[STEP 1] Identify Problem Word
  → Extract the key terms repeatedly used in the argument.

[STEP 2] Analyze Meaning by Usage Context
  → What meaning was the same word used for in each speech context?

[STEP 3] Detect Semantic Shift Point
  → Point out the exact spot where the meaning subtly changed.

[STEP 4] Declaration of Dismissal
  → "This argument is an equivocation fallacy that uses the same word with a different meaning. Dismissed."
`

## 📌 Reference Case: Shift in Definition of "Explicit"

| Point of Utterance | Definition of "Explicit" | Purpose |
|:---|:---|:---:|
| Early Rebuttal | "Directly declared in a single verse" | Dismiss Calvary theory |
| After Presenting Trinity Counterexample | "Structural connection of multiple verses is also explicit" | Save the Trinity |
| Upon Re-attacking Calvary Theory | "Not explicit if there is no single verse declaration" | Dismiss Calvary theory again |

> **TYPE-AL Verdict**: The definition of "explicit" changed at least twice during the argument.
> This is an equivocation fallacy. A consistent definition is demanded.
> Upon applying a consistent definition — the Calvary theory falls into the explicit category with the same structure as the Trinity. ✅

## 🆕 Sub-Protocol: TYPE-AL-cap — Capitalization Self-Check (Homonyms) — v1.1

> **Invocation Conditions**: When attempting to apply the conclusion of a verse containing an uppercase divine title (Son, Spirit, Word, etc.) directly to a lowercase general usage of the same root. It is **mandatorily applied to our own (BVCAP) argument** as well as the opponent's argument.
> **Reference**: The list of homonyms registered in section 7 (Uppercase/Lowercase Divine Title Alert Table) of `02_TACTICS(Tactics)/LEXICON_Bible.md`.

```
[STEP 1] Identify Capitalization Pair
  → Check whether the word used in the argument is registered in the table of LEXICON section 7.
  → If not, add the newly discovered pair to section 7 (living document principle).

[STEP 2] Original Language Check — True Distinction or Editorial Capitalization?
  → Do the two usages actually have different vocabulary/grammatical structures in the original language (Greek/Hebrew)?
  → Is the original Old Testament text (e.g., Ps 2:7) quoted by the uppercase usage a separate specific utterance formula (such as a coronation declaration)?
  → YES (There is an actual distinction) → Go to STEP 3
  → NO (The word itself is the same, merely contextual judgment by KJV editors) → Demote the uppercase notation to an "auxiliary signal" and prohibit its use as the sole basis for a conclusion

[STEP 3] Determine Automatic Transfer
  → Is the conclusion of the uppercase usage "directly applied" to the lowercase usage, or is it "irrelevant to this argument"?
  → If irrelevant, exclude that verse from the list of evidence for the given conclusion.

[STEP 4] Declaration of Verdict
  → "This verse (uppercase usage) only proves [specific declaration/meaning]. It does not prove regarding [lowercase general category]."
```

### 📌 Reference Case: Heb 1:5 "Son" → Job 38:7 "sons" Automatic Transfer Fallacy (2026-07-19)

```
[STEP 1] Identify Pair: Son (Heb 1:5, quoting Ps 2:7) vs sons (Job 1:6·38:7, בְּנֵי הָאֱלֹהִים)

[STEP 2] Original Language Check:
  The "Son" in Heb 1:5 quotes a specific coronation declaration formula ("this day have I begotten thee") in Psalm 2:7.
  The "sons of God" in Job 1:6·38:7 is a separate Hebrew idiom (בְּנֵי הָאֱלֹהִים) — an indicator of a creation category.
  → Confirmed separate strata of utterance in the original language (coronation declaration vs creation category name)

[STEP 3] Automatic Transfer Determination:
  Heb 1:5 only proves "an angel has never received a Ps 2:7 style coronation declaration."
  "Whether the sons in Job 38:7 are angels or not" is a separate question irrelevant to Heb 1:5.
  → Irrelevant → Excluded from the list of evidence

[STEP 4] Verdict: Heb 1:5 does not prove "angel = son is absolutely impossible."
  The conclusion "sons in Job 38:7 ≠ angels" can be maintained, but it must be established only upon independent evidence such as the time of creation, sang/say vocabulary,
  and ἀρχή rule.
```
